# ADR-401: Display width for wide characters

## Context

Layout, label centring, and the canvas measure text by rune count. A CJK
character or an emoji occupies two terminal columns, so a node labelled
`日本語テキスト` is sized for seven columns and rendered across fourteen,
and its right border lands outside the box. `docs/upstream-parity-audit.md`
ranks this first among the gaps against termaid.

`go.mod` has no dependencies and the README says so. A display-width
function is either a dependency (`mattn/go-runewidth`) or a generated
table vendored into the repository.

## Decision

### A vendored table

`internal/textwidth` provides `Rune(r rune) int` and `String(s string)
int`. The width of a rune is 0 for combining marks, zero-width joiners,
and variation selectors; 2 for East Asian Wide and Fullwidth characters
and for emoji presentation characters; and 1 otherwise. The ranges come
from `EastAsianWidth.txt` and `emoji-data.txt` of Unicode 16 and are
emitted by `tools/gen-widths/main.go` as sorted `[2]rune` range tables in a
generated file that records the Unicode version. Regenerating is
`go generate ./internal/textwidth`.

Ambiguous-width characters are 1. `MMAID_AMBIGUOUS_WIDE=1` makes them 2
for terminals configured that way; ADR-500 folds that into the profile.

### What zero dependencies means

The binary depends on the Go standard library and nothing else. Data
tables derived from public standards may be vendored when they are
generated by a tool in the repository from a named upstream version, so
that a reader can reproduce them. Code from other modules is not
vendored. `go.mod` stays without a `require` block.

### Where width applies

Every place that measures a string for layout uses `textwidth.String`:
node sizing in `internal/layout/grid.go`, `drawLabel`, edge labels,
subgraph labels, and every diagram renderer that centres or pads text.
`Canvas.PutText` advances by rune width and stores a continuation marker
in the second cell of a wide rune so that a later single-cell write over
either half clears both. `ToString` and `ToColorString` skip continuation
cells. The ADR-101 interpreter advances by the same function and writes
codepoint 0 into continuation cells.

### Gate

The `wide-label` fixture of ADR-101 is re-recorded; its borders align.

## Consequences

### Positive

- CJK and emoji labels fit their boxes.
- The rule is reproducible from a named Unicode version.
- No dependency.

### Negative

- The generated table is about 200 lines and a tool to maintain.
- Grapheme clusters are not handled: a flag emoji made of two regional
  indicators is measured as 4. Terminals disagree on that case as well.
- Ambiguous width is a per-terminal fact the table cannot know.

### Neutral

- `len(s)` on a label is a bug wherever it remains; a test greps the
  layout and renderer packages for `len(` applied to a label field.

## Alternatives Considered

- **`mattn/go-runewidth`.** Rejected: it is the reference implementation
  and the first dependency in a project whose README promises none; its
  tables are the same standard's tables, and it carries an East Asian
  locale heuristic this project replaces with an explicit setting.
- **`golang.org/x/text/width`.** Rejected for the same reason and it
  lacks emoji presentation data.
- **Treat everything above U+2E80 as wide.** Rejected: box-drawing and
  symbols this renderer emits are above that range and narrow.
