# Contributing to mmaid

mmaid renders Mermaid diagrams as terminal art in Go with no dependencies
beyond the standard library. Contributions that keep it that way are
welcome: new diagram types, renderer fixes, glyph sets, docs.

## Before you start

- Open an issue first for anything larger than a fix. A diagram type or a
  renderer change usually needs a decision recorded first; see below.
- Read `.claude/CLAUDE.md`. It says how to see what you render and what
  gates a change. The same rules apply to people.
- Read the ADRs that touch your area: `docs/scripts/adr list --group`.
  The renderer is ADR-400, ADR-401, ADR-402; routing is ADR-102; layout is
  ADR-103 and ADR-104; the test loop is ADR-101; configuration is ADR-500.

## The loop

```bash
make build                                  # ./mmaid
make snap FILE=testdata/fixtures/x.mmd      # .snap/x.png with rulers, plus lint findings
make golden                                 # every fixture against its reference frame, then the lint
make golden-record                          # rewrite references and docs/gallery after an intended change
make check                                  # what CI runs
```

Look at the PNG, not the terminal. A tool result or a pasted terminal drops
columns and substitutes glyphs.

## Rules the code keeps

- Lines are drawn through `Arm`, `Segment`, or `PutBox`; never a literal
  box-drawing rune. Fills, arrowheads, and markers come from the `CharSet`.
  Label widths come from `textwidth`. (ADR-400, ADR-500, ADR-401)
- Every line end is closed by an arm, a fed arrowhead, or text. The
  structural lint enforces it and has no exceptions. (ADR-402)
- `testdata/fixtures/known-bad.txt` is empty. A fixture that trips the lint
  is fixed, not listed; if it must be listed, the line carries a one-line
  cause and an issue.
- Zero dependencies: the standard library plus data tables generated by a
  tool in this repository from a named upstream version. (ADR-401)

## Adding a diagram type

1. Read the Mermaid docs page and, where the page is thin, the grammar in
   the Mermaid repository. Note the commit you read.
2. Add the parser under `internal/diagram/` (or `internal/parser/` when it
   targets the flowchart engine), with `// Read:` and `// Skipped:` blocks
   at the top listing what the grammar has that you do and do not parse.
3. Wire `detectDiagramType` and `Render` in `mmaid.go`, `--demo` and
   `printUsage` in `cmd/mmaid/main.go`, and a README table row.
4. Add a fixture in `testdata/fixtures/`, record it, and rebuild the gallery.
   It must pass the lint.

## Pull requests

- One decision per PR. If the PR needs an ADR, the ADR is the first commit:
  `docs/scripts/adr new <domain> "Title"`, status `Proposed`; it becomes
  `Accepted` when the PR merges.
- Conventional commits: `feat(scope):`, `fix(scope):`, `docs:`, `test:`,
  `build:`. A commit that re-records goldens says which frames changed and
  why in its body.
- `make check` and `make golden` clean; `gofmt -l` clean on touched files.
- Prose in commits, comments, and docs says each thing once.

## Reporting

Bugs and feature requests use the issue templates. For a rendering bug,
attach the Mermaid source and the output of
`mmaid --cells - your.mmd` (a text frame) or a `make snap` PNG.
